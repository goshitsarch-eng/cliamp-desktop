# Desktop QA walkthrough

## Application and environment

Tested the Godot desktop player on November 21, 2026. The initial checkout was `5d05ca35` (`v2.4.0-19-g5d05ca35`). The walkthrough used desktop builds reporting **0.1.0**. Desktop **0.1.1** includes the fixes recorded below.

| Component | Tested configuration |
| --- | --- |
| Host | macOS 27.0.1, build 26A434, Apple M2 Max, arm64 |
| Frontend | Godot 4.7.2 stable ed1daf0bf, Compatibility renderer, OpenGL 4.1 Metal. The bundle has arm64 and x86_64 frontend slices. |
| Playback | Go 1.26.11, arm64 CGO sidecar, system codec libraries, built-in audio device, FFmpeg for FLAC fixtures and HLS. The frontend uses Godot's dummy audio driver. |
| Build | Built the Go player with the pinned Go toolchain, imported the Godot project and exported the macOS .app. Installed Homebrew pkgconf for codec discovery. The development export uses ad-hoc signing. |
| Windows | Windows 11 on ARM build 26300.9974, Parallels Desktop 27.1 on the M2 Max. Tested the x64 export under Windows emulation, OpenGL 3.3 via Parallels Metal, and the per-user Inno Setup installer with its six codec/runtime DLLs. |
| Linux | Debian GNU/Linux 13 arm64 and amd64 under QEMU, X11 with Xvfb/Openbox and Mesa llvmpipe. The arm64 walkthrough used EGL and a clocked PulseAudio test sink. The x86_64 executable and Flatpak also ran in the amd64 guest. |
| Test data | Separate temporary home, macOS preferences, player config, data, cache and runtime directories. Generated WAVs, embedded plain and timed FLAC lyrics, RSS, M3U, PLS, HLS and a disposable Lua plugin. No personal libraries or provider credentials were required. |

The native bundle was opened through Launch Services and controlled with macOS mouse, keyboard, menus and file sheets. The repeatable windowed scenarios start the actual desktop main scene with the real Go engine. They send input to rendered controls, query independent engine state where applicable and save screenshots. Some scenarios seed data through IPC, set dimensions directly, or inject recorded error conditions. Unit and headless integration tests provide separate evidence.

Development starts at `godot/project.godot` → `ui/main.tscn` and `ui/main.gd`. The autoloads `Backend`, `Store` and `Prefs` connect to the engine, publish state and restore the desktop window. The Go executable enters through `main.go` and serves V2 IPC. See the [desktop guide](desktop.md) for source launch, platform dependencies, packaging, configuration, keyboard shortcuts and workflows. The [control-by-control results](desktop-audit-controls.md) record the observed individual selections.

The defect ledger contains 32 product defects, including one critical data-loss issue, 17 high, 13 medium and one low. Six additional findings cover the reliability of the test environment and harness.

## Layout, input and regression checks

- Captured every page at requested client sizes of 960 × 600, 1280 × 800, 2200 × 700, 960 × 1300 and 1920 × 1080, plus maximized and restored. A request for 20 × 20 checked minimum enforcement. The renderer and the window manager can clamp requested sizes.

## Remaining acceptance limits

- The macOS native-window backend emitted closed-window diagnostics during modal dismissal with accessibility enabled. A standalone Godot project containing a stock ConfirmationDialog reproduced the display-server diagnostics outside Cliamp. Focus restoration, Cancel/Open, repeated modals and shutdown were exercised on the application. This remains an open framework diagnostic.
- End-to-end commercial playback, genuine third-party sign-in/device verification, third-party scrobbling services and other private media-server catalogs require accounts, entitlements, hosts or credentials absent from the disposable test environment. Service schema selection, input, an unreachable server, saved test configuration and restart were exercised. Radio location consent was exercised in separate temporary profiles. Refusal kept it disabled. Allowing the synthetic Europe/Oslo timezone completed consent. The provider derives the country locally.
- Windows ran in an ARM guest with x64 emulation. Debian used virtual software displays and a test sink. The amd64 GLX driver reported that it cannot change VSync. The arm64 EGL run avoided that warning. An initial unclocked ALSA null output consumed a 90-second fixture immediately, so it could not establish playback timing. The strict runner treats a warning as a failure, even when every interaction assertion completes. These runs do not verify bare-metal Windows/Linux graphics, physical audio fidelity, device switching on a second device, global hardware media keys, or spoken screen-reader output. The macOS accessibility bridge exposed only part of the main window. Late in the audit the native automation tool reported “Sky Computer Use native pipe startup failed.” Earlier native clicks, menus and file sheets were exercised. The final bundle relaunch used Launch Services, its real engine readbacks and window captures. The separate windowed walkthrough continued to send pointer and keyboard events to Godot controls.
- The staged x86_64 Flatpak was built, installed per-user, updated and opened in the Freedesktop 25.08 runtime. In the installed package, Ctrl-clicking two WAV files returned both exact paths to the queue. The fallback chooser also accepted a typed absolute path and rejected a missing filename. Distribution-store delivery, a from-source Flatpak SDK build and the GNOME/KDE native portal grant lifecycle remain unverified. The universal macOS frontend ran on Apple silicon. Its bundled development engine is arm64.
- macOS supplies Services, window tiling and native file-browser UI. Selected application-facing window actions and native file workflows were exercised. Operations that involve unrelated applications, personal files, shares, or invoking an external macOS service were outside the disposable fixture. The desktop frontend has no file-drop target, standalone document editor, or general-purpose Save As/export dialog.

## Performance and logs

The packaged app remained responsive while loading a 205-entry queue and while an HTTP fixture held an import open for cancellation. Five samples at three-second intervals on a paused four-track queue showed the frontend at 1.7–3.7% CPU and 232–234 MiB resident. The owned engine used 0.0–0.2% CPU and about 69 MiB resident. These are short observations on this host. They cannot establish a long-duration memory trend.

The final exported app also repeated the self-save through Cmd+S. Both WAVs had SHA-256 `3c01e20726832f75b5e2759b8fe065d928dcda3255dff9c7a262bcc35c0d2fc2`.

During a repeat cold boot, the four-vCPU Debian arm64 guest stopped answering SSH. Its serial console reported a kernel watchdog hard lockup on CPU 1 and a soft-lockup taint in the idle thread. The test resumed from the saved guest disk with two vCPUs. The raw kernel diagnostic is included with the run logs.

The installed Flatpak also logged a host warning about its per-user PulseAudio socket symlink. The guest had an explicit test socket. The sandbox could query that audio server, and the player returned an advancing position. The virtual GLX display separately logged its inability to change VSync.

The native frontend log recorded the Godot macOS focus diagnostic described above. Its Go log recorded normal startup, provider registration and the expected skips for unconfigured services. The evidence archive also includes the isolated framework reproduction.
